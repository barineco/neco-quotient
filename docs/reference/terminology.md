# 用語索引

この文書では、neco-quotient の公開文書で使う語から、その対象と関係を定義する文書へ案内します。各語の意味は、参照先に記載した関係と成立条件によって定まります。

## 観測と商

### 観測関数族

対象の型を $X$、観測結果の型を $V$ とするとき、関数 $X \to V$ の集まりです。二つの対象に全ての関数を適用した結果が一致するとき、その二つを観測関数族について同値とします。詳細は [観測関数族と商](../concepts.md) を参照してください。

### 観測尺度

観測関数族が定める同値関係によって決まる、対象を区別する細かさです。異なる観測関数族が同じ同値関係を定める場合、観測尺度も同じです。

## 入力と参照

### `SourceRef` ( 入力参照 )

入力の識別子とリビジョンの組です。証明書と期待値が同じ入力を指すことは、両者の `SourceRef` の一致によって確かめられます。

### `revision` ( リビジョン )

入力の一時点を識別する値です。規則のリビジョンは、独立した `rule_revision` または `ruleRevision` の欄で表されます。

### `source`

証明書が参照する入力を表す欄です。値は `SourceRef` であり、入力を取得した場所や通信経路とは区別されます。

## 証明書

### `Certificate` ( 証明書 )

入力、座標、同一視に用いる観測、射影ダイジェスト、残余、証拠を規則のリビジョンに結び付ける値です。照合が成立する条件は [証明書](../certificate.md) で定めます。

### `observations` ( 観測 )

証明書がどの観測によって対象を区別するかを表す値です。具体的な型は、その値から観測関数族を得る対応を定めます。状態遷移を扱う `StatefulRule` では、入力列の集まりから、各入力列に対する出力列を返す観測関数族を得ます。

### `ProjectionDigest` ( 射影ダイジェスト )

射影の名前、ダイジェストの文字列、比較できる範囲の組です。照合では三つの値をまとめて比較します。ダイジェストの形式は規則ごとに定まり、SHA-256 は選択できる形式の一つです。

### 証明書のハッシュ値

証明書全体を正規のバイト列へ変換し、SHA-256 を適用した値です。射影ダイジェストとは別の値です。

### `residuals` ( 残余 )

照合後も区別として保持する値の集合です。二つの残余集合は、要素の所属が一致するとき同じ集合とみなされます。通信形式には、一意な要素が正規の順序で収録されます。

### `evidence` ( 証拠 )

証明書の作成側が記録し、射影ダイジェストの再計算に用いる値です。照合が成立すると、証明書の射影ダイジェストは、同じ入力、座標、観測、証拠から再計算した値と一致します。

### `provenance` ( 来歴 )

照合を呼び出した側が渡し、不一致が生じた場合に `Mismatch` が同じ値を保持する情報です。

## 照合

### `admit` ( 照合 )

証明書、期待値、リビジョンに対応する規則を受け取り、[証明書](../certificate.md) に定める一致条件を順に確かめる処理です。

### `Checked` ( 照合済み )

全ての一致条件が成立した証明書と再計算結果を保持する値です。公開 API では `admit` の成功からだけ得られます。

### `Mismatch` ( 不一致 )

照合を終了させた最初の条件、その条件の期待値と実際の値、証明書の入力参照、来歴を保持する失敗です。

## 精密化

### 観測関数族の精密化

精密化前の観測関数族を $D$、精密化後を $D'$ とします。$D$ の各観測に、その確定済み結果を保存する観測が $D'$ に存在するとき、$D'$ は $D$ を精密化します。

$$
\forall o\in D,\;\exists o'\in D',\;\operatorname{RefinesObs}(o,o')
$$

Lean では `ObservationFamilyRefines`、Rust では `ObservationRefines` がこの前後関係と証拠を表します。

### `VerifiedRefinement` ( 検証済みの精密化 )

同じ入力について、精密化前後の観測、評価結果、残余集合、評価証拠を結び付ける値です。前の段階で確定した判定は、後の段階の評価でも同じ値として得られます。

## 保持判定

### `preserved_observations` ( 保存する観測 )

実体化解除の後も結果を取得できる状態に保つ観測の列です。復元不能な手段では、`removed_observations` との共通部分に含まれる観測ごとに `ObservationNotPreserved` が成立します。

### `Dematerialize` ( 実体化解除 )

保持理由が空のときに、データの実体を破棄し、以後の取得を復元手段に委ねられることを示す判定結果です。

### `Retain` ( 保持 )

一つ以上の保持理由が成立したことを、その理由の列とともに示す判定結果です。

### `Rejected` ( 判定不能 )

復元手段または復元不能になる観測の宣言が不足していることを示す結果です。不足を補った入力は、保持または実体化解除の判定へ進みます。
