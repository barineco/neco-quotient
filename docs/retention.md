# 保持の判定

呼び出し側が `ErasureRequest.target` に関連付けた値を、以下「データ」と呼びます。データには、保存済みの成果物と、再計算できる一時的な値の両方が含まれます。データが保存先やメモリに配置され、その実体から直接取得できる状態が「実体化」です。

保持判定は、対象の利用状況と復元手段、関連する観測を受け取り、実体を保持する理由または実体化解除の証拠を返します。実際に削除や復元を行うのは、判定結果を受け取った側です。

## 観測の指定

`ErasureRequest` は、観測について次の二つの列を持ちます。

- `removed_observations`: 採用した復元手段が再現の対象から除く観測
- `preserved_observations`: 実体化解除の後も結果を取得できる状態に保つ観測

復元手段が `Irrecoverable` の場合、二つの列の共通部分に含まれる観測は、実体化解除によって結果の取得手段を失います。

$$
\mathrm{removed\_observations}\cap\mathrm{preserved\_observations}
$$

共通部分の各要素は `ObservationNotPreserved` という保持理由になり、対象の実体は保持されます。共通部分が空で、ほかの保持理由も空である場合、`Dematerialize` が成立します。

## 判定の入力

| 入力 | 表す関係 |
|---|---|
| `ErasureRequest` | 対象、対象の基底、復元の対象から除く観測、実体化解除の後も結果の取得を保つ観測 |
| `LiveSet` | 有効な基底、分岐の根、将来の利用、未完了の作用と信号 |
| `Option<Recoverability>` | 採用した復元手段、または復元手段が未確定であること |

入力の提供側は、対象に関係する利用と未完了の作用を網羅した `LiveSet` を渡します。復元手段の参照と証拠は対象のデータに対応し、復元結果は、その手段が再現の対象から除く観測 ( `removed_observations` ) 以外について、元の結果と一致する必要があります。

## 判定の結果

| 結果 | 成立条件と値 |
|---|---|
| `Dematerialize` | 保持理由が空であり、対象、復元手段、復元の対象から除く観測を返す |
| `Retain` | 一つ以上の保持理由が成立し、判定条件の順に理由を返す |
| `Rejected` | 復元手段または復元不能になる観測の宣言が不足し、不足した入力の種類を返す |

保持理由は、有効な基底や将来の利用、未完了の作用、結果の取得手段を失う観測など、判定条件の順に求められます。同じ対象が利用の列に複数回現れても、理由は利用の種類ごとに一つです。

## 適用の境界

`Dematerialize` は、対象に関連付くデータの実体を破棄し、将来の取得を宣言済みの復元手段へ委ねられることを示します。元の対象や来歴、判定に用いた証拠は、以後の復元と照合のために判定結果を受け取った側が保持します。
